# 互评与反馈

## 适合

- 想得到具体、可执行、不打击人的反馈。
- 做同伴互评、工作坊、章节试读意见整理。
- 收到很多读者意见，不确定哪些应该采纳。
- 给别人做反馈时，不知道怎么组织才能帮到对方。

## 核心判断

好反馈不是把问题全部倒给作者，而是帮助作者看见**文本已经有效的部分、最影响阅读的问题，以及下一步最值得改什么**。反馈的目的是让作品变得更好，不是证明读者比作者厉害。好的反馈会区分"读者感受"和"修改命令"——前者是数据，后者才是建议。

## 操作方法

### 1. 先说有效之处

在指出任何问题之前，明确告诉作者文本里有生命力的部分：一个有效的人物动作、一句有力的对话、一段让读者沉浸的氛围、一个巧妙的悬念设置、一个成功的情感瞬间。

反馈不说优点只列问题的后果：作者不知道应该保留什么，可能在修改时把好的部分也改掉。

### 2. 先问作者目标

反馈要服务于作者的目标。同一个片段，目标不同需要不同的评价标准：

| 作者目标 | 反馈重点 |
|---------|---------|
| 写快节奏连载 | 钩子够不够、章节收益是否清楚 |
| 写文学性短篇 | 语言密度、意象统一、余韵 |
| 写商业类型长篇 | 结构是否完整、类型承诺是否兑现 |
| 写第一稿草稿 | 优先看故事发动机，不纠句子 |

### 3. 问题要具体，不要空泛

| 无效反馈 | 有效反馈 |
|---------|---------|
| "节奏太慢" | "第2章到第4章主角没有主动行动，三章里换了三个地点但没有升级冲突"|
| "人物不可信" | "第5页主角拒绝了100万的交易，但前文没有任何铺垫说明他不缺钱或有道德洁癖" |
| "对话太假" | "第3段对话中A说'你知道吗，我们家族两百年来一直守护着这个秘密'——但A和B是兄妹，B不可能不知道" |

### 4. 每轮最多抓三件事

问题超过三个读者记不住，作者也改不过来。先抓最影响阅读的三项，其他的可以在下一轮再提。

优先级建议：
- 第一优先：阻碍读者理解故事的问题（因果断裂、动机缺失、信息混乱）
- 第二优先：影响读者投入的问题（主角不主动、冲突不足、悬念不够）
- 第三优先：可以等下一轮再修的问题（句子风格、描写密度、节奏微调）

### 5. 区分读者感受和修改命令

读者可以说"我在这里困惑了""这里读起来有点慢""我不确定这个人物为什么这样做"。这些是**读者感受数据**，如实传达给作者。

但读者感受不等于修改命令。作者需要自己决定：是否修改、怎么修改、是否符合自己的写作目标。

### 6. 反馈不是投票

工作坊的目的是帮作者理解文本在读者眼中的效果，而不是投票决定故事应该怎么写。不同读者对同一段文本有不同感受是正常的。当读者意见冲突时，优先看哪个意见和作者的目标更一致。

## 常见陷阱

- **反馈变成重写**：读者太投入地告诉作者"应该怎么写"，而不是告诉作者"我读到了什么"。
- **只讲缺点**：不给任何肯定，作者改完后失去了原有特色。
- **把个人偏好当标准**："我不喜欢第一人称"——但这不是文本的问题。
- **过度吹毛求疵**：挑出所有小问题，让作者不知道该从哪开始改。
- **反馈服务于读者自我展示**：反馈中大量展示读者自己的阅读量和写作知识，而不是服务于文本。

## 快速诊断

- 文本最有生命力的部分是什么？
- 最影响阅读的三件事是什么？
- 哪个问题最优先？
- 作者的目标是什么？这次反馈是否服务了这个目标？
- 哪些反馈意见只是读者感受，不一定要修改？

## 网页端复制块

```text
请用"三优三改"的方式反馈这段小说。

正文：
{正文}

作者目标：
{目标}

请输出：
1. 三个优点：每个优点说明为什么有效
2. 三个修改点：每个修改点给出具体位置、原因和改法
3. 一个最优先修改的问题
4. 一个不建议改动的地方
5. 如果你作为读者，最想继续看的点是什么
6. 哪些反馈只是读者感受，不一定要照单全收

语气要求：具体、直接、但不要打击作者。
```
