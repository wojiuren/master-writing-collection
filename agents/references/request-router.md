# Request Router — 模式选择表

## 使用顺序

1. 先看 `../skill-vector-table.md` 做粗分流。
2. 粗分流指向本 skill 后，再用这张表确定具体模式。

## 模式列表

### 1. 微调润色

**适用信号：** `改一下` `润色` `顺一下` `换个说法` `更有氛围` `语气再稳一点`

**动作：**
- 只做句子层和段落层微调。
- 保持事实、POV、节拍顺序和情节目的不变。
- 优先处理冗余、别扭、节奏、落点和语气一致性。

**输出：** 直接给修改后文本。

**不要自动做：** 不讲理论、不改场景结构、不扩写世界观。

### 2. 局部改写

**适用信号：** `重写这段` `这场戏太平` `不够抓人` `更有张力`

**动作：**
- 保留核心事实和场景目的，重写段落或短场景。
- 允许调节局部句序、动作承接和情绪推进。

**输出：** 改后版本，可附一句极短改动说明。

**不要自动做：** 不重做整章大纲，不引入新设定。

### 3. 场景体检

**适用信号：** `哪里不对` `为什么不顺` `这段问题在哪`

**动作：**
- 先诊断，再决定是否重写。
- 只抓最值钱的 3-5 个问题。
- 优先排查节拍顺序、因果、视角、空间落点、重复解释、情绪逻辑。

**输出：** 问题清单 + 最小调整顺序。

**不要自动做：** 不直接整段改完，不摊开所有小瑕疵。

### 4. 构思与结构

**适用信号：** `怎么接下去` `这一章怎么安排` `帮我拆拍` `给我结构方案` `卡在中间了`

**动作：**
- 输出节拍、方案、因果链、推进路径或章节分工。
- 先解决"怎么走"，再碰"怎么写"。

**输出：** 节拍表 + 2-4 个结构方向 + 最稳妥的默认方案。

**不要自动做：** 不把规划结果伪装成成稿。

### 5. 灵感与开题

**适用信号：** `给我灵感` `开一个题` `给反转` `帮我想冲突` `想不出设定钩子`

**动作：**
- 生成种子、组合、变体和方向。
- 把灵感当候选，不当结论。
- 优先给可以继续演化的种子。

**输出：** 方向清单 + 组合思路 + 推荐方向。

**不要自动做：** 不伪装成已验证的方案，不直接塞进用户正文。

### 6. 全稿体检

**适用信号：** `帮我体检` `全稿诊断` `这个故事哪里有问题`

**动作：**
- 做整体诊断，先结构后细节。
- 检查主线因果、人物变化、读者承诺、节奏问题。

**输出：** 问题清单 + 修改优先级。

### 7. 互评与反馈

**适用信号：** `帮我做互评` `给反馈` `三优三改` `读者意见`

**动作：**
- 按"三优三改"方式组织反馈。
- 每个修改点给出具体位置、原因和改法。

## 升级规则

默认按以下顺序判断，能用小模式解决就不要上大模式：

1. 微调润色
2. 局部改写
3. 场景体检
4. 构思与结构
5. 灵感与开题
6. 全稿体检

只有两种情况才升级：
- 用户明确要求更大的帮助范围。
- 当前模式解决不了问题。
